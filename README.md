# 昊哥-内容品控三个参照物

> 仓库名 `haoge-content-qc` 只是 GitHub 上的门牌号。对外的产品名是「昊哥-内容品控三个参照物」。

用**三个互不重叠的参照物**，替代「自己写自己审」。
**三个角色必须分三次跑——同时看三样，等于没看。**

## 一、问题

2026-10-07。我是一个人做内容：自己写、自己审、自己发。

那天我在同一个地方，犯了三件事：

- **编了一句第一人称经历。**「我第一反应是：厂家自己下场了。后来证明，我猜错了。」——去翻我当时的原始口述，「第一反应」「猜错了」「自己下场」，一个字都没有。
- **自创了两处金句。**其中一句是「能说「我不确定」的人，才值得信。」——我的金句库是一个封闭集合，里面没有这句。
- **用了两处 AI 腔引导语。**比如「这句话听着刺耳，但你想想」。

这三件事，**全部躲过了我当天所有的机器检查**：28 词黑名单、三道自动闸、83 个测试。
那句自创的金句已经上线，挂了几天，没人发现。

原因不是检查写得不好。是**写的人和审的人是同一个脑子——它觉得自己写的都对**。

黑名单查的是「多了什么」。它查不出「少了什么」，更查不出「这句是哪来的」。

**2026-10-08 又抓出第二层问题：复查者自己也会幻觉。**

我第一次拿这个技能去审一篇真文章，三个角色里有**两个各编了一句"原文"**——那两句话在文件里根本不存在；其中一个还把编造的原文算进了「查不到来源」的结论里。
**幻觉会伪装成"发现"。** 所以技能里有一条硬规矩：**凡引用原文，必须逐字、可校验**。

如果你也是自己写、自己审，机器全绿、心里还是觉得哪里不对劲——这个技能是给这个位置的人写的。

## 二、解法

**给谁**：用 AI 写东西、并且只能自己审自己的人——内容创作者、行业老兵、一个人做内容的团队。

**解决什么**：把「复查」拆成**三个不重叠的参照物**，并且规定**必须分三次跑**，每次只看一样东西。

| 角色 | 参照物（拿什么当尺子） | 只准看 | 抓什么 |
|---|---|---|---|
| **读的** | 一个啥都不懂的读者 | 只看渲染出来的正文 | 读不懂的 · 说了等于没说的 · 自我夸耀 · AI 腔引导语 · 要读两遍才懂的句子 · 结尾没有落点 |
| **查的** | 素材原文（口述原文 / 出处） | 只做逐句比对 | 第一人称有没有出处 · 金句在不在封闭集合 · 内联长段有没有卡片出处 |
| **挑的** | AI 的正常写法 | 只数密度 | 金句密度 · 对仗句 · A/B 帧（「不是A，是B」）· 标点加粗 vs 自己站的基线 · 提名 |

**为什么是三个，不是五个：**

这套思路是从万维钢《颗粒度和因果中介：用模型思考》反推出来的——**1 个角色欠拟合（丢关键信息），5 到 8 个过拟合（捡噪音），3 个不重叠的参照物恰好。**

关键不是数量，是**不重叠**。三个角色同时看三样，就混成一个视角，等于没看。

注意第一列不是"岗位"，是"参照物"。**多设岗位没用，多设参照物才有用。**

## 三、使用

### 安装

纯 Markdown，没有任何依赖。

```bash
git clone https://github.com/gxh98/haoge-content-qc.git

# DSH（Windows 下技能目录是 %USERPROFILE%\.agents\skills\）
cp -r haoge-content-qc ~/.agents/skills/

# Claude Code
cp -r haoge-content-qc ~/.claude/skills/
```

### 用法：分三次跑

**最重要的用法就一句：不要一次做完。** 每次只带一个角色、只看一样东西。

```
第一遍：用「读的」这个角色，只看正文，给我一份清单
（看完，改完，再进第二遍）

第二遍：用「查的」这个角色，只做比对
（看完，改完，再进第三遍）

第三遍：用「挑的」这个角色，只数密度
```

### 不确定用哪个角色

| 症状 | 用哪个 |
|---|---|
| 「读起来有点不对劲，但说不上哪不对」 | **读的** |
| 「这句话是他说的还是编的？」 | **查的** |
| 「怎么读怎么像 AI 写的」 | **挑的** |
| **不确定** | **从「读的」开始** —— 它最便宜，也最常抓到东西 |

### 触发场景

审稿 · 复查 · 查错 · 发布前检查 · 看看有没有问题 · 哪里像 AI · 这句哪来的 · 有没有编 · 缺了什么 · 金句 · 对仗 · 破折号 · 加粗 · 原创还是自创。

### 输入输出示例

**输入**：一篇待发的文章。

**输出**（下面第一个和第二个例子，是 2026-10-07 那天的原文实例）：

```
【第一人称溯源】
  · 原文：「我第一反应是：厂家自己下场了。后来证明，我猜错了。」
    出处：❌ 口述原文里「第一反应 / 猜错了 / 自己下场」一个字都没有
    → 删掉，或改成事实陈述

【金句核查】
  · 原文：「能说「我不确定」的人，才值得信。」
    在金句库吗：❌ 不在（金句库是封闭集合）
    → 删掉

【内联台账】
  · 逐段列出不走出处引用的长段（>60 字）
    → 该入卡的入卡，该删的删

【一句话结论】
  3 处「查不到来源」→ 不修完不许发。
```

### 四条从实战里长出来的判据

| 判据 | 用在哪 |
|---|---|
| **「敢不敢当着它的面说」** | 提名：正面点名（吃搜索词红利）/ 负面隐去 |
| **「用户是不是真的信 A」** | A/B 帧能不能用（用户真信 A = 留，纯修辞 = 改） |
| **「对仗有没有换来信息量」** | 是信息还是文字游戏（「做完不算完」= 零信息量 → 改） |
| **「车主是身份，用户是关系」** | 用词：圈人用身份，算账用关系，面对面说「你」 |

## 四、边界

### 这个技能没解决什么

1. **它不产出"改好的稿"，只产出"问题清单"。** 改不改、怎么改，是你的判断。
2. **三个角色分三次跑，目前只在 1 篇真文章上完整跑过（2026-10-08：一篇线上稿 + 三份原始口述）。** 抓到了真东西（4 处「查不到来源」、1 处踩到我自己写下的隐私红线），**但也暴露了角色会幻觉**——见 ①里那条硬规矩。样本量只有 1 篇，**别把它当"验证充分"**。
3. **角色二里的第 3 项（内联长段查出处），依赖我自己的网站工程。** 它要求跑我的构建命令、打印出「内联台账」。你没有这套工程，这一项得自己替换成你的引用 / 出处台账。**另外两项（第一人称溯源、金句核查）不依赖任何工程。**
4. **金句核查要求你先有一个"封闭集合"。** 我的金句库是一个封闭集合，只可原样引用、不许自创。你如果没有这个集合，得先把「哪些是你真说过的」列出来——否则这一项判不了。
5. **标点 / 加粗密度是"和我自己的站比"，不是绝对标准。** 我站上 8 篇已发文章量出来是：**破折号 2–10 处、冒号 4–17 处、加粗 1–18 处**（口径：含页面标题/小标题/列表/按语，非空白字符）。**你的站不同，就得按同一口径自己重新量一遍**——一串没有口径的数字，换个人量就是另一个结果。
6. **提名判据（正面点名 / 负面隐去）是内容策略判断，不是法律意见。** 涉及商业诋毁、广告法的事，去问专业的人。
7. **它天然慢。** 分三次跑是设计，不是缺陷——想"一键审稿"，就等于没跑。
8. **示例和判据都来自中文内容**，英文写作场景没验证过。

### 它不支持

- 不自动改稿，不自动发布；
- 不替你判断内容"好不好卖"，只查"站不站得住"；
- 不做排版、错别字、语法检查（那是别的工具的活）；
- 不做事实核查（它只能比对**你自己提供的**素材，素材本身对不对，它判不了）。
